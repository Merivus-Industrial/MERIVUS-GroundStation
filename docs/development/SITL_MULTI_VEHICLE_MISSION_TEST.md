# SITL 编队与多机独立任务测试

本文只适用于 PX4 SITL / Mock 环境，不用于自动连接或操作真实无人机。

## 功能语义

- 普通点击车辆是排他单选；之前车辆正在执行的任务不会因切换焦点而中断。地图框选用于显式多机操作。
- 左侧“起飞”在没有框选时保持 QGC 原有单机行为；有框选时，对框选车辆执行批量起飞。
- 左侧“编队”恢复既有 SITL swarm 语义：目标必须恰为 UAV-1～UAV-6，UAV-1 收到启动包后作为主机，UAV-2～UAV-6 跟随；该入口不会读取或启动任何机载 Mission。
- 编队协议只在启动 QGC 前显式设置 `MERIVUS_DEV_ENABLE_SWARM_LEGACY_FORWARDING=1` 时开放，界面会显示启用状态。
- Shift+右键的首个航点会冻结目标 ID 和当时的几何关系；释放 Shift 后确认上传临时 Mission。自动执行还要求 `MERIVUS_DEV_ENABLE_SWARM_AUTO_START_MISSION=1`。
- 同一车辆已有临时任务时，新 Shift 队列需要明确确认替换；普通右键单点按 MOBA 语义即时抢占并执行新目标。
- 临时任务到达末航点并悬停后请求清除机载 Mission；清除失败会标记为残留任务，不能被当作新任务静默启动。
- 多机下发使用 200 ms 间隔，属于近同步启动，不是飞控时钟级同步。
- 六机编队任一目标不满足条件时整组拒绝；普通多机指令仍可逐机跳过不合格目标。

## 启动 QGC 前启用开发开关

PowerShell：

```powershell
$env:MERIVUS_DEV_ENABLE_SWARM_LEGACY_FORWARDING = "1"
$env:MERIVUS_DEV_ENABLE_SWARM_AUTO_START_MISSION = "1"
.\MERIVUS.exe
```

Linux shell：

```bash
export MERIVUS_DEV_ENABLE_SWARM_LEGACY_FORWARDING=1
export MERIVUS_DEV_ENABLE_SWARM_AUTO_START_MISSION=1
./MERIVUS
```

环境变量必须在启动 QGC 前设置；运行中修改不会更新界面显示的启用状态。

## 切换车辆时的 Plan 弹窗

QGC Plan View 只有一个当前编辑器。切换活动车辆不会中止原车辆正在执行的任务，也不允许把上一架车辆的编辑草稿保留到新连接车辆上下文。

- “放弃未保存的更改，从车辆加载新方案”：丢弃编辑器中未保存/未上传的修改，然后从新选中的车辆读取它自己的 Mission、GeoFence 和 Rally Point。
- 连接车辆之间切换时不再提供“保留当前方案，不从车辆更新”，从 UI 上消除把上一架任务上传给新车辆的旁路。
- 只有车辆断开并进入离线编辑上下文时，才允许保留当前离线草稿。

要让各机执行不同任务，推荐流程如下：

1. 选择 UAV-1，在 Plan View 规划并上传 UAV-1 的任务。
2. 确认上传完成、编辑器不再显示未保存/未发送状态。
3. 切换 UAV-2；若出现弹窗，只能选择“放弃未保存的更改，从车辆加载新方案”。
4. 为 UAV-2 规划并上传不同任务；其他车辆依次重复。
5. 回到 Fly View 后，各机的普通右键或 Shift 任务保持独立；不要使用“编队”启动这些任务。

如果某架机的方案尚未上传，先保存到文件或完成上传再切换车辆。不要用“保留当前方案”充当每架机独立草稿存储。

## 批量起飞验收

前置条件：至少启动两架 PX4 SITL，多机均完成初始连接、定位和健康检查，均处于地面未飞行状态。

1. 在 Fly View 用左键拖框选择两架或更多车辆。
2. 核对左侧摘要显示框选数量和 ID。
3. 点击“起飞”，确认条应显示框选数量和冻结后的车辆 ID。
4. 设置高度并确认。
5. 观察每架通过检查的 SITL 车辆进入起飞流程并在目标相对高度附近悬停。
6. 让其中一架断链或制造健康检查失败后重复；该机应出现在“已跳过”列表，其他合格车辆仍收到命令。
7. 清空框选后点击“起飞”；应恢复为只控制当前活动车辆。

## 固定六机 SITL 编队验收

1. 按文首要求启用 SITL 编队开发开关，启动 UAV-1 主机和五架从机。
2. 框选 UAV-1～UAV-6；确认界面应固定显示 UAV-1 为主机、2～6 为从机。
3. 确认后，UAV-1 应先起飞，五架从机按机载 swarm 逻辑跟随完成默认正方形轨迹并悬停。
4. 编队执行期间按钮应切换为“结束编队”；不能重复启动另一编队事务。
5. 断开 UAV-1 遥测超过 3 秒，QGC 应停止转发并让仍在线的从机悬停。
6. 仅断开一架从机时，其余编队继续，QGC 显示缺员告警。
7. 缺少任意一架、目标不是完整 1～6、任一目标未就绪或未开启 SITL 开关时，整组拒绝启动。

## 跨机实时任务隔离验收

1. 单选 UAV-1，普通右键下达目标 1；随后单选 UAV-2 下达目标 2。
2. UAV-1 应继续飞向目标 1，UAV-2 独立飞向目标 2；切换焦点本身不能发送或中止任务。
3. 框选多机并普通右键时，以冻结几何圆心计算平移量，各机保持相对间距平行移动。
4. 给 UAV-1 绘制 Shift 多航点任务；绘制过程中切换目标应取消草稿，不能把已画路线交给新目标。
5. UAV-1 执行 Shift 任务时再次给 UAV-1 绘制新队列，确认界面必须明确提示替换；取消时旧任务继续。
6. UAV-1 执行 Shift 任务时普通右键新目标，应立即抢占旧队列，不弹替换确认。
7. UAV-1 执行任务时切换到 UAV-2，UAV-1 任务不中断；两机地图只显示各自当前任务。
8. Shift 任务完成后应悬停并清除临时 Mission；再次切回该机时不得恢复旧路线。

## 安全边界

- 本功能仍使用 QGC `Vehicle` / `MissionManager` 的人工确认链路，不接入 AI proposal 执行。
- `MERIVUS_DEV_ENABLE_SWARM_LEGACY_FORWARDING` 和 `MERIVUS_DEV_ENABLE_SWARM_AUTO_START_MISSION` 均默认关闭，且只允许用于 SITL/开发环境。
- 旧编队启动包没有正式 ACK；“启动信号已发送”不等于编队已开始或已完成，SITL 验收仍需观察每架机状态和轨迹。
- 正式实机编队必须另行设计版本化命令、逐机 ACK、事务 ID 与机载失联保护，不得直接解除当前开发开关。
