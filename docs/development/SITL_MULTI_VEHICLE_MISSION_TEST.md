# 六机编队、多机动作与独立任务测试

本文只适用于 PX4 SITL / Mock 环境，不用于自动连接或操作真实无人机。

## 功能语义

- 普通点击车辆是排他单选；之前车辆正在执行的任务不会因切换焦点而中断。地图框选用于显式多机操作。
- 左侧“起飞”“降落”“返航”在没有多选时保持 QGC 原有单机行为；框选多机时，对冻结目标逐机执行，失败目标进入“已跳过”。
- 批量返航统一使用标准 RTL；Smart RTL 只保留给单机操作。
- 左侧“编队”恢复既有 swarm 语义：目标必须恰为 UAV-1～UAV-6，六机收到版本 `1` 启动命令后，UAV-1 作为主机、UAV-2～UAV-6 跟随；该入口不会读取或启动任何机载 Mission。
- 编队和 Shift 临时任务默认启用，不再依赖 `MERIVUS_DEV_ENABLE_SWARM_*` 环境变量。
- Shift+右键的首个航点会冻结目标 ID 和当时的几何关系；释放 Shift 后通过顶部滑动或长按空格确认上传临时 Mission。
- 同一车辆已有临时任务时，新 Shift 队列需要明确确认替换；普通右键单点按 MOBA 语义即时抢占并执行新目标。
- 临时任务到达末航点并悬停后请求清除机载 Mission；清除失败会标记为残留任务，不能被当作新任务静默启动。
- 多机下发使用 200 ms 间隔，属于近同步启动，不是飞控时钟级同步。
- 六机编队任一目标不满足条件时整组拒绝；普通多机指令仍可逐机跳过不合格目标。

## 启动方式

直接启动 MERIVUS 即可。界面应显示“六机编队：已启用”，Shift 多航点也无需额外环境变量。

## 切换车辆时的 Plan 弹窗

QGC Plan View 只有一个当前编辑器。切换活动车辆不会中止原车辆正在执行的任务，也不允许把上一架车辆的编辑草稿保留到新连接车辆上下文。

- “放弃未保存的更改，从车辆加载新方案”：丢弃编辑器中未保存/未上传的修改，然后从新选中的车辆读取它自己的 Mission、GeoFence 和 Rally Point。
- 连接车辆之间切换时不再提供“保留当前方案，不从车辆更新”，从 UI 上消除把上一架任务上传给新车辆的旁路。
- 只有车辆断开并进入离线编辑上下文时，才允许保留当前离线草稿。
- 只有编辑器存在未保存修改时才弹出深色中文确认框；干净方案直接加载新无人机任务。
- 切换车辆不会自动弹出“继续任务”，该动作只允许从动作列表主动触发。

要让各机执行不同任务，推荐流程如下：

1. 选择 UAV-1，在 Plan View 规划并上传 UAV-1 的任务。
2. 确认上传完成、编辑器不再显示未保存/未发送状态。
3. 切换 UAV-2；若出现弹窗，只能选择“放弃未保存的更改，从车辆加载新方案”。
4. 为 UAV-2 规划并上传不同任务；其他车辆依次重复。
5. 回到 Fly View 后，各机的普通右键或 Shift 任务保持独立；不要使用“编队”启动这些任务。

如果某架机的方案尚未上传，先保存到文件或完成上传再切换车辆。不要用“保留当前方案”充当每架机独立草稿存储。

## 批量起飞、降落与返航验收

前置条件：至少启动两架 PX4 SITL，多机均完成初始连接、定位和健康检查，均处于地面未飞行状态。

1. 在 Fly View 用左键拖框选择两架或更多车辆。
2. 核对左侧摘要显示框选数量和 ID。
3. 点击“起飞”，确认条应显示框选数量和冻结后的车辆 ID。
4. 设置高度并确认。
5. 观察每架通过检查的 SITL 车辆进入起飞流程并在目标相对高度附近悬停。
6. 让其中一架断链或制造健康检查失败后重复；该机应出现在“已跳过”列表，其他合格车辆仍收到命令。
7. 清空框选后点击“起飞”；应恢复为只控制当前活动车辆。
8. 多机悬停后保持框选，依次测试“降落”和“返航”；确认条应冻结同一批目标。
9. 批量返航应对各机调用标准 RTL；批量界面不显示 Smart RTL 选项。
10. 制造一架断链后执行降落或返航；该机应进入“已跳过”，其他合格无人机继续执行。

## 单机、双机、六机 SITL 编队验收

1. 依次以 UAV-1、UAV-1+任一从机、UAV-1～UAV-6 运行同一验收流程。
2. PREPARE 只有在成员本机预检通过后才返回最终 ACK；任一拒绝应触发整组 ABORT。
3. COMMIT 期间应持续收到 IN_PROGRESS；每架到达起飞高度并进入 Ready 后才返回最终 ACK。
4. 地面站只有在全部成员 Ready 后才发送 RELEASE；全部 RELEASE ACK 后按钮切换为“结束编队”。
5. 点击“结束编队”，检查成员收到 USER_4 ABORT，地面站停止租约，各机转入 AUTO_LOITER。
6. 分别在 PREPARE、COMMIT 和 RELEASE 阶段断开一架成员；其余已接受成员必须收到 ABORT。
7. 断开 UAV-1 遥测超过 3 秒，QGC 应整组 ABORT。
8. 直接退出 QGC，所有成员应在最后一个 `FOLLOW_TARGET` 后不超过约 3 秒进入 AUTO_LOITER。
9. 重放旧会话命令或旧 `FOLLOW_TARGET`，机载端应因会话 ID 或 source 不符而拒绝。
10. 选择不含 UAV-1 的目标、三至五架目标、重复 ID 或六机非完整 1～6 时，地面站拒绝启动。

## 跨机实时任务隔离验收

1. 单选 UAV-1，普通右键下达目标 1；随后单选 UAV-2 下达目标 2。
2. UAV-1 应继续飞向目标 1，UAV-2 独立飞向目标 2；切换焦点本身不能发送或中止任务。
3. 框选多机并普通右键时，以冻结几何圆心计算平移量，各机保持相对间距平行移动。
4. 给 UAV-1 绘制 Shift 多航点任务；绘制过程中切换目标应取消草稿，不能把已画路线交给新目标。
5. UAV-1 执行 Shift 任务时再次给 UAV-1 绘制新队列，确认界面必须明确提示替换；取消时旧任务继续。
6. UAV-1 执行 Shift 任务时普通右键新目标，应立即抢占旧队列，不弹替换确认。
7. UAV-1 执行任务时切换到 UAV-2，UAV-1 任务不中断；两机地图只显示各自当前任务。
8. Shift 任务完成后应悬停并清除临时 Mission；再次切回该机时不得恢复旧路线。

## 安全边界

- 本功能仍使用 QGC `Vehicle` / `MissionManager` 的人工确认链路，不接入 AI proposal 执行。
- 编队和临时任务默认可用，但编队仍要求明确框选完整 UAV-1～UAV-6 并通过人工确认。
- 编队启动/停止具备标准 MAV_CMD ACK，但 ACK 只表示命令参数已被飞控接收；它不等于编队已起飞、已建立或已完成，验收仍需观察每架机状态和轨迹。
- 配套机载源码位于 `E:\MERIVUS\FirmwarePX4`，Pixhawk 6C Mini 构建目标是 `px4_fmu-v6c_default`。真实飞行验收仍必须使用逐机状态观察、拆桨/系留等现场安全流程，并由人员手动执行。
