# SITL 多机起飞与独立任务测试

本文只适用于 PX4 SITL / Mock 环境，不用于自动连接或操作真实无人机。

## 功能语义

- 地图框选结果是后续批量动作的目标集合；打开确认条时会冻结目标 ID，确认期间继续改变框选不会改变本次命令目标。
- 左侧“起飞”在没有框选时保持 QGC 原有单机行为；有框选时，对框选车辆执行批量起飞。
- 左侧“编队”不再发送旧版 GPS 转发包，而是让框选车辆分别启动各自已经上传到机载端的任务。
- 多机下发使用 200 ms 间隔，属于近同步启动，不是飞控时钟级同步。
- 任一车辆不满足链路、健康状态、飞行状态、任务存在或任务同步空闲条件时会被跳过，不影响其他已通过检查的车辆。

## 切换车辆时的 Plan 弹窗

QGC Plan View 只有一个当前编辑器。切换活动车辆时，弹窗处理的是这个编辑器中的方案，不会直接删除或改写其他飞控已经保存的机载任务。

- “放弃未保存的更改，从车辆加载新方案”：丢弃编辑器中未保存/未上传的修改，然后从新选中的车辆读取它自己的 Mission、GeoFence 和 Rally Point。
- “保留当前方案，不从车辆更新”：保留编辑器当前内容，只把管理车辆切换到新车辆并将方案标记为已修改。之后若点击上传，当前编辑器内容可能被上传到新车辆，因此不适合查看各机已有的不同任务。

要让各机执行不同任务，推荐流程如下：

1. 选择 UAV-1，在 Plan View 规划并上传 UAV-1 的任务。
2. 确认上传完成、编辑器不再显示未保存/未发送状态。
3. 切换 UAV-2；若出现弹窗，选择“放弃未保存的更改，从车辆加载新方案”。
4. 为 UAV-2 规划并上传不同任务；其他车辆依次重复。
5. 回到 Fly View，框选要共同启动的车辆，点击“编队”，核对冻结的目标 ID 后确认。

如果某架机的方案尚未上传，先保存到文件或完成上传再切换车辆。不要用“保留当前方案”充当每架机独立草稿存储。

## 批量起飞验收

前置条件：至少启动两架 PX4 SITL，多机均完成初始连接、定位和健康检查，均处于地面未飞行状态。

1. 在 Fly View 用左键拖框选择两架或更多车辆。
2. 核对左侧摘要显示框选数量和 ID。
3. 点击“起飞”，确认条应显示框选数量和冻结后的车辆 ID。
4. 设置高度并确认。
5. 观察每架通过检查的 SITL 车辆进入起飞流程并在目标相对高度附近悬停。
6. 让其中一架断链或制造健康检查失败后重复；该机应出现在“已跳过”列表，其他合格车辆仍收到命令。
7. 清空框选后点击“起飞”；应恢复为只控制当前活动车辆。

## 各机独立任务启动验收

1. 分别给 UAV-1、UAV-2 上传路径明显不同的任务。
2. 切换车辆并从车辆重新加载，确认两架机显示的航点不同。
3. 回到 Fly View 框选 UAV-1、UAV-2。
4. “编队”按钮应由禁用变为可用；点击后确认条应列出两架机 ID。
5. 确认后，结果弹窗应分别列出已下发和已跳过的车辆。
6. 两架机应进入各自机载 Mission，而不是共享当前活动车辆的编辑器任务。
7. 任一车辆没有机载任务、正在同步、断链、健康检查不允许启动或已经处于 Mission 模式时，应只跳过该机。

## 安全边界

- 本功能仍使用 QGC `Vehicle` / `MissionManager` 的人工确认链路，不接入 AI proposal 执行。
- 旧版 `MERIVUS_DEV_ENABLE_SWARM_LEGACY_FORWARDING` GPS 转发入口仍默认关闭，左侧“编队”不依赖该环境变量。
- “命令已下发”不等于飞控 ACK、任务已开始或任务已完成；SITL 验收还需观察每架机状态和轨迹。
