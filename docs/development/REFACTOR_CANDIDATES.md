# 重构候选

这些项目不是本轮必须改动。只有出现对应需求或测试证据时再实施。

| 候选 | 现状 | 触发条件 | 建议边界 |
| --- | --- | --- | --- |
| FTC 后端拆分消息族 | 一个 FactGroup 管理四类消息 | 属性继续明显增长或需要独立单测 | 保留一个 QML 门面，内部按 Motor/Control/Extreme/Diagnostics 分类 |
| 电机卡片组件化 | 卡片 delegate 位于大文件 `CommandCenterOverlay.qml` | 卡片需要支持不同旋翼数和布局 | 抽成产品 QML 组件，输入 ESC 与 FTC 类型化模型 |
| 状态文本翻译表 | C++ `switch` 集中映射 | 协议枚举频繁扩展 | 使用只读表驱动，仍由 C++ 提供唯一语义 |
| 超时配置化 | 版本 1 固定 3 秒 | 消息率按链路模式显著变化 | 后端按契约给出每族超时，不能由 QML猜测 |
| 方言源单一发布物 | 两仓各存相同核心 XML并用哈希校验 | 建立可靠的跨仓依赖发布流程 | 发布带版本和 SHA-256 的协议包；不改成运行时下载 |
| Vehicle 领域门面 | Vehicle 暴露大量 FactGroup | 新产品模块持续增长 | 保持 Vehicle 兼容属性，新增聚合只读门面并逐步迁移 |

不要为了缩短文件而拆分。重构必须同时减少重复事实源、保持 QML API 稳定，并有消息回放或 UI 测试兜底。
