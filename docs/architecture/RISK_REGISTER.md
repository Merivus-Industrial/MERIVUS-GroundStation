# MERIVUS 风险清单

风险级别：P0 最高，P3 较低。

| 编号 | 级别 | 风险 | 当前证据 | 建议缓解 |
| --- | --- | --- | --- | --- |
| R-001 | P0 | AI 或 UI 绕过统一安全策略直接执行飞行动作 | AI 面板已进入 C++ proposal 策略和只显示建议；指挥中心仍可直接下发高度/速度/爬升 | 继续保持 AI `executable=false`；后续对非 AI 指挥中心入口增加确认、审计和权限 |
| R-002 | P0 | 多机任务上传和启动缺少完整前置检查 | `SwarmController` 可上传临时任务并 `startMission` | 独立审计 `SwarmController`，增加 feature flag、确认、审计、Mock/SITL 验证 |
| R-003 | P1 | 编队协议仍缺少逐机运行状态与事务关联 | 启停已改为版本化 `MAV_CMD_USER_1/2` + ACK；位置使用带标识的 `FOLLOW_TARGET`，不再伪装 `GPS_RAW_INT` 控制字段 | 保持禁止 AI 调用；补充逐机能力/状态消息、事务 ID 与 SITL 故障注入 |
| R-004 | P0 | 真实飞机测试被自动化触发 | 用户描述已有实机无桨测试，但 Codex 禁止自动测试真实飞机 | 文档和流程中明确只用 Mock/SITL/回放；真实测试需人工授权 |
| R-005 | P1 | 4G 链路延迟、卡顿、断线导致控制体验不稳定 | HyperLTE 手册提醒 4G 网络存在延迟和卡顿 | 阶段 1 做 Link 诊断、超时、错误提示；失联保护依赖 PX4 |
| R-006 | P1 | 视频链路占用或阻塞影响控制链路 | 控制和视频同走 4G 网络，手册区分数传/图传端口 | 视频与 MAVLink 独立队列和状态；视频失败不影响 Link |
| R-007 | P1 | TCP/IP/端口硬编码导致现场不可维护 | 用户描述端口需配置化；代码未发现业务硬编码，但缺少专用配置层 | 阶段 1 明确配置入口和诊断显示 |
| R-008 | P1 | Agent 离线或崩溃影响 UI | 当前 AI 面板直接 QML 网络请求，无进程监管 | 阶段 4/5 C++ client + supervisor；离线降级 |
| R-009 | P1 | 发布包依赖开发机路径 | 构建脚本使用固定 Qt/VS 路径；发布包方案未完成 | 阶段 15 做相对路径和 AppData 配置 |
| R-010 | P1 | 硬件供电接错或供电不稳导致模块损坏/重启 | HyperLTE 为 5-36V 输入，推荐 12V 稳压独立供电；Hyper982 成品模块 VCC 为 3.6-6.0V，推荐 5V，禁止直接接 12V | 接线前必须核对实际硬件版本、接口定义、电压范围和串口电平；分别记录 HyperLTE 与 Hyper982 供电方案 |
| R-011 | P2 | RTK 数据被误判为通信服务能力 | Hyper982 当前定位/定向，不承担通信服务器 | 文档明确 RTK 只是定位源；不把 RTK 当设备网关 |
| R-012 | P2 | GIS 显示数据被误用为碰撞计算数据 | 当前未发现独立 GIS Safety Service | 阶段 13 明确 DEM/DSM/矢量数据和未知区域策略 |
| R-013 | P2 | 多机 ID、sysid、设备 ID 映射混乱 | 当前 QGC 使用 Vehicle id；未来有 4G 设备和云端 ID | 设备网关 POC 前定义映射契约 |
| R-014 | P2 | 未提交的用户改动与审计文档混杂 | 审计前已有 QML/SVG 修改和 `docs/hardware/` 未跟踪 | 不回滚；本次只新增架构文档，最终说明清楚 |
| R-015 | P3 | 根目录说明与仓库实际不一致 | 任务提到可能有 `AGENTS.md`，实际根目录没有 | 后续可补充仓库级 `AGENTS.md` 或同步文档 |

## 最大安全风险

当前最大安全风险是高风险飞行动作入口已经散落在 QML 和 `SwarmController` 中，而统一 C++ 白名单、风险重算、确认、审计尚未形成。

## 最大网络风险

当前最大网络风险是 4G 链路天然存在延迟、卡顿、断线和厂商云依赖；如果视频和控制链路没有严格隔离，拥塞时可能影响心跳与控制。

## 最大发布风险

当前最大发布风险是产品仍处于 QGC 源码构建形态，Agent、配置、日志、Qt 运行库、许可证和 AppData 写入策略尚未形成完整 Windows 发布包。

## 已经验证

- Windows 环境检查通过。
- Release 增量构建通过。
- 硬件 PDF 存在并可抽取关键事实。

## 用户描述但尚未验证

- 真实 4G 链路 `119.45.168.211:62178` 当前仍可用。
- 无桨实机测试表现。

## 待确认事项

- 是否优先修复 AI/Swarm 高风险入口。
- 是否把 `docs/hardware` 纳入仓库。
- 是否先做 Link 基线再做 AI 收敛。

## 阶段 6 新增缓解

- `AiSchemaValidator` 限制 proposal 结构、大小、深度和危险字段。
- `AiCommandPolicy` 固定白名单并本地重算风险。
- Agent 伪造的风险、确认和执行字段会被忽略。
- AI 面板没有新增真实执行入口。
- 审计只记录脱敏策略摘要。

剩余 P0 风险转移到后续确认框架、非 AI 指挥入口审计、真实任务上传与 SwarmController 隔离。
